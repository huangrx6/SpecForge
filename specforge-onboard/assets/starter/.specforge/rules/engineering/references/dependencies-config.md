# 依赖、配置和外部服务

本参考用于新增依赖、升级依赖、调整配置项和接入 backing service。

## 新增依赖

新增依赖必须说明：

- 用途。
- 替代方案。
- 体积或运行时成本。
- 维护状态。
- 兼容性风险。
- 是否会改变构建、部署或安全面。

不要为少量逻辑引入重量级依赖。

## 依赖升级

依赖升级应记录：

- 目标版本。
- 升级原因。
- breaking change 风险。
- 迁移动作。
- 验证范围。
- 是否影响锁文件、构建产物或运行环境。

如果升级本身就是主要工作，不要把它混进无关 feature。

## 配置项

配置项设计必须说明：

- 默认值策略。
- 环境差异。
- 校验方式。
- 缺失或非法时的失败提示。
- 是否影响兼容性。
- 是否需要文档更新。

## 环境差异

- 开发、测试、预发、生产差异通过配置表达。
- 不把生产、测试、开发值硬编码到代码。
- 配置读取失败要有可理解错误。
- 运行所需的外部资源句柄应通过配置注入。

Twelve-Factor 把 backing service 视为可替换资源，并强调通过配置切换资源句柄，而不是把环境差异写死在代码里。

## 外部服务

接入数据库、缓存、消息、搜索、第三方 API 时，至少说明：

- 超时。
- 重试。
- 熔断或降级。
- 失败时用户或上游看到什么。
- 依赖不可用时是否有替代路径。

## Review Checklist

- 新依赖是否真的必要。
- 配置是否可校验、可解释、可部署。
- 外部服务接入是否有失败模式。
- 依赖升级是否有明确验证范围。
