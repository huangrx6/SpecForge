# Observability Capability

用于日志、指标、trace、健康检查、告警和问题定位设计。

## 适用

- 新增后台任务、外部调用、AI 调用、支付 / 订单 / 审批等关键链路。
- 需求需要排障、SLA、调用耗时、失败率或业务结果可追踪。
- 线上问题定位目前依赖人工翻日志或无法关联请求。

## 设计必填

- 关键链路的 request id / trace id / task id 如何贯穿？
- 需要哪些结构化日志字段、指标和告警阈值？
- 健康检查、启动检查和依赖检查如何区分？
- 失败、重试、降级和人工介入如何被观测？
- 日志中哪些字段必须脱敏或禁止输出？

## 验证

- 本地或测试环境能看到关键日志、指标或 trace 摘要。
- 失败路径有可定位的错误码、上下文和关联 ID。
- 不输出 token、密码、密钥、完整个人敏感信息。
