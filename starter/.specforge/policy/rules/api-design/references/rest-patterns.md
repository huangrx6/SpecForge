# REST 设计模式

本参考用于 REST / HTTP API 的资源建模、URI、method、状态码、幂等、缓存和查询参数设计。

## 资源优先

REST API 应围绕资源建模，而不是围绕动作建模。

| 目标 | 推荐 | 避免 |
|---|---|---|
| 用户集合 | `GET /users` | `POST /getUsers` |
| 单个用户 | `GET /users/{user_id}` | `GET /user?id=123` |
| 创建用户 | `POST /users` | `POST /createUser` |
| 更新用户 | `PATCH /users/{user_id}` | `POST /updateUser` |
| 用户订单 | `GET /users/{user_id}/orders` | `GET /getUserOrders` |

命名规则：

- 集合用复数名词，例如 `/users`、`/orders`、`/products`。
- 路径使用小写和连字符，例如 `/shipping-addresses`。
- 嵌套不要过深，通常不超过两层资源关系。
- 过滤、排序、搜索、字段选择放在 query 参数中。

## HTTP 方法语义

| 方法 | 安全 | 幂等 | 常见用途 |
|---|---|---|---|
| `GET` | 是 | 是 | 读取集合或单个资源 |
| `POST` | 否 | 否 | 创建资源或执行非幂等操作 |
| `PUT` | 否 | 是 | 整体替换资源 |
| `PATCH` | 否 | 通常否 | 局部更新资源 |
| `DELETE` | 否 | 是 | 删除资源 |
| `HEAD` | 是 | 是 | 读取元信息 |
| `OPTIONS` | 是 | 是 | 查询支持的方法 |

设计要求：

- `POST` 创建成功应返回 `201`，并尽量提供 `Location`。
- `DELETE` 成功且无响应体时返回 `204`。
- 异步任务返回 `202`，同时提供任务资源或状态查询方式。
- 幂等写入场景应支持 `Idempotency-Key` 或业务唯一键。

## 状态码选择

| 类别 | 状态码 | 使用场景 |
|---|---|---|
| 成功 | `200` | 读取、更新并返回资源 |
| 成功 | `201` | 创建资源成功 |
| 成功 | `202` | 已接受，异步处理中 |
| 成功 | `204` | 成功但无响应体 |
| 客户端错误 | `400` | 参数格式或请求结构错误 |
| 客户端错误 | `401` | 未认证或认证失败 |
| 客户端错误 | `403` | 已认证但无权限 |
| 客户端错误 | `404` | 资源不存在或不可见 |
| 客户端错误 | `409` | 状态冲突、重复提交、并发修改 |
| 客户端错误 | `422` | 语法正确但业务校验失败 |
| 客户端错误 | `429` | 触发限流 |
| 服务端错误 | `500` | 未预期服务端错误 |
| 服务端错误 | `502` | 上游返回异常 |
| 服务端错误 | `503` | 服务暂不可用 |
| 服务端错误 | `504` | 上游超时 |

不要用 `200` 包装业务失败。失败应通过状态码、稳定错误码和错误响应共同表达。

## 查询参数

| 目的 | 约定示例 |
|---|---|
| 过滤 | `GET /users?status=active&role=admin` |
| 排序 | `GET /users?sort=-created_at,name` |
| 搜索 | `GET /users?q=alice` |
| 字段选择 | `GET /users?fields=id,name,email` |
| 展开关联 | `GET /orders/{id}?include=items,payments` |

查询参数必须有类型、默认值、允许值、最大值和安全边界。复杂查询如果超过 URL 可读性，考虑建模为搜索资源，例如 `POST /user-searches`。

## 幂等与并发

写操作必须明确重复请求和并发修改的行为。

| 场景 | 推荐做法 |
|---|---|
| 创建支付、订单、任务 | 支持 `Idempotency-Key` |
| 整体替换 | 使用 `PUT`，相同请求重复执行结果一致 |
| 乐观锁 | 使用 `ETag` / `If-Match` 或版本号 |
| 并发冲突 | 返回 `409` 或 `412`，说明如何恢复 |
| 异步执行 | 返回任务资源，允许查询状态 |

## 缓存与条件请求

读取接口应考虑缓存策略：

- 公共可缓存数据：使用 `Cache-Control: public, max-age=...`。
- 用户私有数据：使用 `Cache-Control: private` 或 `no-store`。
- 可对比资源版本：返回 `ETag` 或 `Last-Modified`。
- 条件读取：支持 `If-None-Match`，未变化返回 `304`。
- 条件写入：支持 `If-Match`，版本不匹配返回 `412`。

## Review Checklist

- URI 是否以资源名词为中心，而不是动作。
- method 是否符合安全性和幂等性语义。
- 状态码是否准确表达结果。
- 集合接口是否包含分页、过滤、排序和上限。
- 写操作是否说明幂等、冲突、超时和重试。
- 是否隐藏内部实现细节。
- 是否有示例请求、成功响应和错误响应。
