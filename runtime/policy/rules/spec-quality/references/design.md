# Design 质量

`design.md` 应回答“怎么做”和“为什么这样做”。

## 必须包含

- 方案概览。
- 分析上下文包：代码库约束、外部资料、用户确认和仍需防守的假设。
- 受影响模块和写入范围。
- 关键流程、数据流或时序。
- API、数据库、配置、权限、部署等契约变化。
- 错误处理、日志、可观测性和回滚考虑。
- 测试策略和风险。
- 备选方案与取舍。

设计不得只是代码清单。对 Agent 有价值的设计，是边界、契约、风险和验证路线。

## 常见缺陷

- 只有目录和文件名。
- 没有风险、没有取舍。
- 不说明为何放弃备选方案。
- 不说明后续 verification 如何证明它对。
- 无法追溯到 requirements、brief 中的探索发现或用户澄清。

## Review Checklist

- design 是否覆盖关键需求。
- design 是否追溯到分析证据，而不是凭空生成方案。
- 是否明确契约变化和验证策略。
- 是否写出高风险实现点。
- 是否能指导 tasks 拆分。
