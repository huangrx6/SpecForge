# 产品需求文档系统能力

本能力负责把简报、头脑风暴、产品发现、预研、知识库事实和用户确认转成 SpecForge 产品需求文档。

产品需求文档是产品决策文档，不是需求规格、不是界面设计、不是技术设计、不是任务拆分。它回答做什么、为什么做、给谁做、第一版做什么，而不是怎么实现。

## 产品需求文档负责

- 为什么做。
- 给谁做。
- 解决什么问题。
- 第一版最小可行版本做什么。
- 第一版不做什么。
- 用户价值和业务目标。
- 成功指标。
- 候选功能如何取舍。
- 产品风险、数据风险、AI 风险和交付风险。
- 是否已经可以进入需求阶段。

## 产品需求文档不负责

- 不写最终需求、验收标准或非功能需求编号。
- 不写接口字段、数据库表、组件拆分、测试命令或工程任务。
- 不替用户做产品方向拍板。
- 不把智能体建议写成用户已确认的最小可行版本。

## 核心产物

- 产品决策摘要
- 问题与目标结果
- 目标用户与场景
- 范围与最小可行版本决策
- 候选功能池
- 用户故事与验收种子
- 指标与评估
- 风险与依赖
- 路线图与版本切分
- 交接给需求阶段

## 读取顺序

1. 读取 `references/prd-playbook.md`，确认阶段边界、决策状态、PRD 语言、假设台账和输入转译规则。
2. 读取 `references/output-contract.md`，选择 `prd-lite / prd-standard / prd-deep`。
3. 按工作项类型读取 `references/patterns.md` 中的 1-3 个 pattern，不要全量套用。
4. 需要产品访谈、MVP 切分或开放问题审查时，读取 `references/decision-prompts.md` 的对应 section。
5. 写完后读取 `references/quality-guide.md`。
6. 如果需要外部 PRD 结构视角，读取 `references/external-prd-reference.md`，只吸收结构检查点，不执行外部保存动作。

## 执行流程

1. 检查是否需要产品需求文档。
2. 检查用户确认状态。
3. 选择输出深度：`prd-lite` / `prd-standard` / `prd-deep`。
4. 从简报、头脑风暴、产品发现、预研和知识库建立产品事实表。
5. 识别高影响未知。
6. 必要时执行产品访谈。
7. 建立候选功能池。
8. 裁剪最小可行版本、可选增强、后续版本和不在范围内的内容。
9. 写产品需求文档。
10. 填写产品决策门禁。
11. 写交接给需求阶段。
12. 若可进入需求阶段，`决策状态 = approved-for-requirements`。
13. 否则 `决策状态 = needs-decision / research-needed / blocked-by-conflict`。

## 完成标准

- 产品需求文档能说明为什么做、给谁做、第一版做什么和不做什么。
- 每个最小可行版本项都有来源、取舍理由和确认状态。
- 成功标准至少有一个可观察指标。
- 高影响未知没有被隐藏；有负责人、需要时间和状态。
- AI / 数据 / 合规 / 运营风险在适用时可见。
- 交接给需求阶段的内容足以让 `sf-requirements` 转译行为种子。
- 产品需求文档没有写成需求规格、界面设计、技术设计或任务计划。
