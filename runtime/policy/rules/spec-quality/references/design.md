# Design 质量

新流程将设计拆为两个 artifact：

- `ui-design.md` 回答“用户如何看见、理解和操作”。
- `technical-design.md` 回答“工程上怎么做”和“为什么这样做”。

## 必须包含

- 方案概览，且明确本设计属于 UI 还是技术。
- 分析上下文包：代码库约束、外部资料、用户确认和仍需防守的假设。
- UI 设计必须包含页面地图、关键流程、视觉风格确认、交互状态和原型证据。
- 技术设计必须包含受影响模块、写入范围、关键流程、数据流或时序。
- 技术设计必须包含 API、数据库、配置、权限、部署等契约变化。
- 技术设计必须包含错误处理、日志、可观测性和回滚考虑。
- UI 和技术设计都必须包含验证策略和风险。
- 备选方案与取舍。

设计不得只是代码清单。对 Agent 有价值的设计，是边界、契约、风险和验证路线。

## 常见缺陷

- 只有目录和文件名。
- 没有风险、没有取舍。
- 不说明为何放弃备选方案。
- 不说明后续 verification 如何证明它对。
- 无法追溯到 requirements、brief 中的探索发现或用户澄清。

## Review Checklist

- UI / technical design 是否覆盖各自影响面。
- UI design 是否先确认风格或明确沿用现有设计系统，而不是进入实现后再临场发挥。
- 设计是否追溯到分析证据，而不是凭空生成方案。
- 是否明确契约变化和验证策略。
- 是否写出高风险实现点。
- 是否能指导 tasks 拆分。
