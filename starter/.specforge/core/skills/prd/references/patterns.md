# PRD Patterns

本文件按工作项类型补充 PRD 必须确认的问题和输出重点。只读取与当前工作项匹配的 1-3 个 pattern；不要全量套用。

## AI Feature

适用：LLM 问答、意图识别、分类 / 抽取 / 生成、智能体工具调用、RAG / 知识库、AI 自动化判断。

必须确认：

- AI 任务是什么。
- 输入是什么。
- 输出是什么。
- 成功质量如何定义。
- 失败如何兜底。
- 是否需要人工复核。
- 是否有敏感数据。
- 成本、延迟、限流边界。
- 是否需要日志、审计、可解释性。
- 是否允许模型不确定 / 拒答。

输出重点：

- AI 任务、评估策略、人工复核 / 覆盖。
- 安全 / 隐私、成本 / 延迟边界、失败模式。
- 交接给需求阶段。

指标示例：抽检准确率、拒答率、人工复核通过率、平均响应时延、单次调用成本、工具调用成功率、安全拦截率。

## B2B Operator Data Product

适用：运营商内部系统、政企 / 大数据 / 客户经理工具、数据看板、领导驾驶舱、任务配置、报表、到期提醒、客户画像、省市县多级权限、敏感客户数据。

必须确认：

- 业务部门 / 使用部门。
- 业务 KPI。
- 目标用户角色。
- 使用频率和设备。
- 数据来源和更新频率。
- 数据口径和指标解释。
- 数据权限、地市权限、脱敏、审计。
- 导出、报表、订阅、告警。
- 灰度、回滚和运维责任。

输出重点：

- 问题 / 目标结果、用户 / 部门、数据与合规快照。
- 范围与 MVP 决策、指标与评估、交接给需求阶段。

常见风险：

- 只写“支持查询”，不写查询对象、口径、权限和频率。
- 只写“数据看板”，不写指标解释和刷新机制。
- 只写“客户经理可见”，不写地市 / 角色 / 数据范围。
- 忘记导出、审计、脱敏和失败兜底。

## Dashboard Report

适用：数据看板、报表、驾驶舱、指标分析、趋势监控、导出订阅。

必须确认：

- 指标定义、口径、粒度和刷新频率。
- 用户角色、查看频率和决策动作。
- 数据源、权限范围、脱敏和审计。
- 空数据、延迟数据、异常值和口径变更提示。
- 导出、订阅、分享、截图或大屏展示是否进入 MVP。

输出重点：

- 期望结果和决策用户。
- 指标与评估。
- 数据与合规快照。
- 候选功能池。
- 指标口径和可测试验收种子。

## Integration Platform

适用：外部服务商、网络回调、SDK、平台能力、开放接口、跨系统同步、集成配置。

必须确认：

- 集成对象和业务价值。
- 输入 / 输出业务语义。
- 服务商是否已确认。
- 失败、超时、限流、重复回调、人工恢复。
- 权限、审计、成本和服务等级影响。

输出重点：

- 问题 / 目标结果、候选功能池、风险与依赖。
- 路线图与版本切分。
- 交接给需求阶段：集成边界、失败种子、决策标记。

## Internal Tool

适用：后台工具、运营工具、配置台、管理端、客服工具、一次性效率工具。

必须确认：

- 操作人角色、频率、权限和责任。
- 当前手工流程和失败代价。
- MVP 要减少哪一步人工操作。
- 审计、回滚、导出和权限边界。
- 是否需要培训、灰度和禁用策略。

输出重点：

- 当前痛点和失败代价。
- 范围与 MVP 决策。
- 产品流程，包含异常路径。
- 风险与依赖。
- 交接给需求阶段：权限、状态、数据文件和运行时种子。

## Workflow Approval

适用：审批、状态流转、发布 / 上线、异步任务、多角色操作、撤回 / 重试 / 驳回。

必须确认：

- 状态有哪些。
- 谁触发状态变化。
- 谁审批。
- 超时怎么办。
- 驳回怎么办。
- 撤回怎么办。
- 失败是否重试。
- 是否通知。
- 是否审计。

输出重点：

- 用户 / 角色、产品流程、异常路径。
- 风险、验收种子、交接给需求阶段。
