# 边界规则

SpecForge 采用边界优先。一个规格的价值在于说明哪些内容可以独立变化，而不会让系统其他部分意外受影响。

## 必答边界问题

每个非 lite change 都应回答：

- 本次变更拥有什么责任？
- 本次变更明确不负责什么？
- 依赖哪些上游契约？
- 如果契约变化，哪些下游区域需要重新验证？
- 哪些文件或模块属于允许写入范围？

## 边界产物

| 产物 | 边界职责 |
|---|---|
| `brief.md` | 候选边界和 workflow 路由 |
| `requirements.md` | 范围、非目标、依赖、验收标准 |
| `design.md` | 边界承诺和文件结构计划 |
| `tasks.md` | 任务级 `_Boundary:_` 和 `_Depends:_` 标注 |
| `code-review-v1.md` | 边界违规发现 |
| `ssot-sync.md` | 长期契约更新 |

## 边界违规

审查时重点标记：

- 未更新规格就编辑批准范围外的文件。
- 给本变更增加属于其他 change 的责任。
- 把上游缺陷隐藏在下游补丁里。
- 创建没有明确 owner 的共享抽象。
- 契约变化后没有重新验证下游依赖。
