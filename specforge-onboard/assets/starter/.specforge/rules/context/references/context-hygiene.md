# 上下文卫生和持久化

本参考用于控制上下文污染：什么该留下，什么只在当前任务里用一下。

## 三类内容

| 类型 | 去向 |
|---|---|
| 长期稳定事实 | `.specforge/knowledge/` 或稳定 rule |
| change 专属事实 | 当前 active change 产物 |
| 一次性调研或推理 | 当前会话或当前 change，除非已经被验证并需要长期保留 |

## 什么时候沉淀

适合沉淀：

- 重复会影响后续决策的项目事实。
- 多个 change 都会用到的工程约束。
- 已拍板的技术决策。
- 已验证的契约和长期行为。

不适合沉淀：

- 纯猜测。
- 暂时 workaround。
- 尚未定案的讨论。
- 特定任务中的偶然观察。

## 摘要优先

上下文治理不是“把资料搬进来”，而是“保留可执行的结论”。

对外部资料或长文档，优先沉淀：

- 关键结论。
- 适用边界。
- 触发条件。
- 反例。
- 链接。

## 常见污染

- 一次性 issue 讨论直接写进规则。
- 某个实现报告被当作长期架构。
- 因为“以后可能有用”而永久保留低价值信息。
- 不区分事实、推测、建议。

## Review Checklist

- 这个信息是否真值得长期保留。
- 是否放在正确层级。
- 是否写清了稳定性和适用范围。
- 是否会在未来误导 Agent。
