# 产品决策边界

## 产品需求文档可以决定

- 为什么做。
- 给谁做。
- 解决什么问题。
- 第一版最小可行版本做什么。
- 第一版不做什么。
- 用户价值和业务目标。
- 成功指标。
- 候选功能如何取舍。
- 哪些风险需要下游处理。
- 是否进入需求阶段。

## 产品需求文档不可以决定

- 接口字段。
- 数据库表。
- 组件拆分。
- 技术栈细节。
- 测试命令。
- 任务排期。
- 最终验收标准编号。
- 具体实现路径。

## 决策状态

| 状态 | 含义 | 是否可进入需求阶段 |
|---|---|---|
| `approved-for-requirements` | 最小可行版本、目标用户、成功标准、非目标已确认 | 是 |
| `needs-decision` | 高影响产品决策未确认 | 否 |
| `research-needed` | 事实不足以决定范围或指标 | 否 |
| `blocked-by-conflict` | 上游输入冲突 | 否 |

## 进入需求阶段的最小条件

- 目标用户明确。
- 核心问题明确。
- 最小可行版本范围明确。
- 非目标明确。
- 成功标准至少有一个可观察指标。
- 高影响未决问题已清零，或有明确负责人和需要时间。
- 交接给需求阶段中有需求种子。

## 确认类型

顶层 `decision_status` 只表达整个产品需求文档是否可进入需求阶段。`delegated-default` 不是顶层状态，只能作为具体最小可行版本项、假设项、范围项或开放问题的确认类型。

| 确认类型 | 含义 | 可进入最小可行版本 |
|---|---|---|
| `user-confirmed` | 用户明确确认 | 是 |
| `delegated-default` | 用户授权智能体按默认建议推进 | 是，但必须写风险、回退点和后续复查触发 |
| `agent-recommendation` | 智能体建议 | 否，只能作为候选 |
| `pending` | 未确认 | 否 |

## 边界修正

| 越界信号 | 修正 |
|---|---|
| 产品需求文档写需求 / 验收编号 | 改成用户故事与验收种子，交给需求阶段转译 |
| 产品需求文档写接口 / 数据库 / 软件开发包 | 移到给技术设计阶段的备注或依赖决策 |
| 产品需求文档写组件 / 颜色 / 布局 | 移到给界面设计阶段的备注 |
| 产品需求文档写测试命令 | 移到验证阶段交接 |
| 智能体建议写成最小可行版本 | 改成候选、授权默认或待确认 |
