# 供应链和安全验证

## 供应链

- 新增依赖前检查来源、维护状态、许可证和安装脚本风险。
- 构建脚本、GitHub Actions、Dockerfile、插件和代码生成器按可执行代码审查。
- 依赖升级应记录安全目的、兼容影响和验证结果。
- 不从不可信 URL 下载并执行脚本。

## 安全验证

安全敏感 change 至少需要：

- 权限正向和反向用例。
- 非法输入、越权、过期 token 或缺失凭据用例。
- 日志脱敏检查。
- 配置和密钥泄露检查。
- 回滚或禁用方案。

## SSDF 视角

NIST SSDF 把安全开发组织为准备、保护、生产安全软件、响应漏洞四类实践，SpecForge 对应地把安全要求放进设计、实现、验证和闭环记录中。
