# Dashboard / Workbench Page

Dashboard 用于监控和决策，Workbench 用于处理任务。后台里的“工作台”默认先按 Workbench 设计，除非用户明确只需要观察指标。

Dashboard 不是指标卡堆叠，也不是侧栏 + 顶栏 + 大空白卡片 + 快捷入口。

## 1. 页面类型选择

| 页面类型 | 适用场景 | 第一屏主角 |
| --- | --- | --- |
| Ops Dashboard | 监控服务、运营指标、异常趋势、业务健康度 | 异常、趋势、阈值、责任入口 |
| Review Desk | 审批、审核、风控、实名、工单处理 | 待处理队列、SLA、详情抽屉、批量动作 |
| Resource Operations | 用户、订单、资源、合同、商品等管理 | 筛选工具栏、主表格、右侧 inspector |
| Executive Overview | 管理层看状态，不直接处理任务 | 业务摘要、趋势解释、风险和下一步建议 |
| Command Surface | AI 工具、运维工具、低频控制台 | 命令输入、推荐动作、历史结果、工具状态 |

如果页面标题是“工作台 / 控制台 / 后台首页”，但用户每天要处理对象，优先选择 Review Desk、Resource Operations 或 Ops Dashboard，不要选择纯指标首页。

## 2. 首屏信息架构

| 区域 | 必须包含 | 说明 |
| --- | --- | --- |
| 顶部控制区 | 时间范围、业务范围、刷新状态、核心过滤 | 让用户知道当前数据口径，不只是搜索框 |
| 主任务区 | 队列、表格、异常列表、时间线、诊断链路或命令面板 | 第一屏必须有可行动对象 |
| 指标区 | 3-5 个可行动指标，或嵌入主任务区的紧凑统计 | 指标必须能解释优先级或跳转对象 |
| 辅助侧栏 | SLA、负责人、最近活动、异常原因、上下文动作 | 不能用通用快捷入口填充 |
| 次级分析区 | 趋势、分布、排名、漏斗、审计或导出 | 只放会影响决策的分析 |

## 3. KPI 规则

每个 KPI 至少满足以下 2 项，否则不要做成大卡片：

| 字段 | 例子 |
| --- | --- |
| 口径 | 今日新增订单，不含取消订单 |
| 时间 | 近 24 小时，更新于 10:24 |
| 阈值 | 高于 95% 正常，低于 90% 警戒 |
| 解释 | 主要增长来自华东区域 |
| 入口 | 点击筛选到对应列表 |
| 动作 | 分派、重试、导出、提醒、查看异常 |

KPI 不应该占满首屏。如果主任务是处理队列，KPI 应该变成表格上方的 compact stat strip 或状态 tabs。

## 4. 工作队列规则

待办、审批、工单、告警必须具备可处理性：

| 字段 | 必填规则 |
| --- | --- |
| 对象 | 订单号、用户名、工单号、资源名或告警名 |
| 状态 | 待审核、处理中、超时、失败、已完成 |
| 优先级 / SLA | 至少一个；有时效风险时两者都要有 |
| 时间 | 创建、触发、到期或更新时间 |
| 负责人 | 多角色、多团队或审批场景必填 |
| 下一步动作 | 审核、分派、查看、重试、忽略、导出 |
| 批量操作 | 重复处理或列表超过 20 条时必填 |

只写“待审核订单 12 条”不是队列，只是摘要。

## 5. 快捷入口规则

快捷入口只有在满足以下条件时才能出现：

- 来自用户角色的高频任务。
- 和当前页面主任务有关。
- 有状态、最近使用、快捷键或权限差异。
- 不占据主任务区或主要侧栏。

否则改成：

| 原问题 | 替代方案 |
| --- | --- |
| 通用 2x2 icon grid | 命令面板 / 顶部 action bar |
| 入口和当前任务无关 | 最近活动 / 最近对象 |
| 入口只是导航重复 | 上下文动作 / 批量动作 |
| 需要展示系统状态 | SLA / 风险 / 责任人面板 |

## 6. 状态矩阵

Dashboard / Workbench 至少覆盖：

| 状态 | 必须说明 |
| --- | --- |
| loading | 骨架屏范围、是否保留旧数据 |
| empty | 首次使用、筛选为空、权限为空的差异 |
| partial | 部分数据源失败时哪些区域降级 |
| stale | 数据延迟、刷新失败和更新时间 |
| error | 数据加载失败、重试和联系渠道 |
| permission | 无权限入口、申请方式、可见范围 |

## 7. 常见失败和修正

| Fail signal | 为什么失败 | 修正动作 |
| --- | --- | --- |
| 4 个大 KPI + 大空白待办卡 | 首屏没有真实工作密度 | 把待办改成工作队列，KPI 降级为状态 tabs 或 compact stats |
| 右侧 2x2 快捷入口 | 只是填充，不服务当前任务 | 换成 SLA、最近活动、异常原因或上下文动作 |
| 待办只有标签和数量 | 不能判断先处理谁 | 补对象、SLA、优先级、负责人、时间和动作 |
| 只有搜索框没有范围控制 | 用户不知道当前数据口径 | 补时间、范围、状态和刷新信息 |
| 卡片高度被拉满但内容少 | 空白被包装成设计 | 删除容器或换成表格、队列、趋势、inspector |

## 8. 验收清单

| 检查项 | 要求 |
| --- | --- |
| 主要使用者 | 明确角色和使用频率 |
| 主要业务对象 | 首屏可见真实对象或异常 |
| 主要任务 | 能看出用户下一步要做什么 |
| 指标 | 有口径、时间、阈值、入口或动作 |
| 队列 | 有对象、状态、优先级 / SLA、时间和动作 |
| 空白预算 | 第一屏无大面积空白 framed card |
| 侧栏 | 承担上下文职责，不只是通用快捷入口 |
| 状态 | loading / empty / partial / stale / error / permission 覆盖适用场景 |
| 验证 | 截图必须能证明主任务区、队列字段和状态矩阵 |
