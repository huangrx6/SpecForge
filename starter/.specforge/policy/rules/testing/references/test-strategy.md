# 测试策略

## 测试分层

| 层级 | 适用场景 | 关注点 |
|---|---|---|
| 单元测试 | 函数、类、组件、小型业务规则 | 快速反馈、边界条件、错误分支 |
| 集成测试 | 数据库、缓存、消息、外部服务适配 | 契约、事务、配置、序列化 |
| 契约测试 | API、SDK、RPC、事件、Webhook | 入参、出参、错误码、兼容性 |
| 端到端测试 | 关键用户流程、跨系统链路 | 主路径、权限、环境配置 |
| 回归测试 | bugfix、历史故障、迁移 | 复现样例不再失败 |
| 手工验证 | UI、部署、第三方环境 | 截图、日志、命令、观察窗口 |

## 风险匹配

| 变更类型 | 最低验证 |
|---|---|
| 文档或模板 | 链接、格式、示例命令检查 |
| 小型纯代码调整 | 相关单元测试或等价命令 |
| API / SDK 契约 | 契约测试、示例调用、兼容检查 |
| 数据迁移 | 迁移前后样例、回滚或补偿验证 |
| 权限和认证 | 正向、反向、越权、过期或缺失凭据 |
| 部署和配置 | 目标环境配置检查、启动检查、回滚步骤 |
| bugfix | 复现失败样例、修复后回归、相邻风险检查 |

## design 中必须写清

- 哪些验收标准由自动化测试覆盖。
- 哪些只能手工验证，以及原因。
- 需要 mock、stub、test container 还是真实环境。
- 外部依赖不可用时的替代验证方式。
