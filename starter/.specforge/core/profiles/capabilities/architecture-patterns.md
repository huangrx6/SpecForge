# Architecture Patterns Capability

用于选择分层架构、模块化单体、事件驱动、插件化、工作流 / 状态机等架构形态。

## 适用

- 需求会改变模块边界、依赖方向、状态机、扩展点或跨系统协作。
- 新增长期能力，后续会被多个页面、接口或任务复用。
- 当前实现存在耦合、重复、状态混乱或难以测试的问题。

## 设计必填

- 选择的架构形态是什么：分层、六边形、模块化单体、事件驱动、状态机或混合？
- 模块边界、依赖方向和禁止依赖是什么？
- 状态流转、事件、命令或扩展点如何表达？
- 迁移策略是一次性替换、双写兼容，还是逐步迁移？
- 哪些边界通过测试、契约或代码结构验证？

## 验证

- 架构边界有代码路径、依赖检查或 review checklist。
- 状态机覆盖成功、失败、重试、取消和异常恢复。
- 事件 / 扩展点有契约和兼容性验证。
