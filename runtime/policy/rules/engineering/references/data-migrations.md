# 数据、迁移和兼容

本参考用于持久化数据、schema、迁移脚本和回滚路径。

## technical_design 必答项

涉及持久化数据时，`technical-design.md` 必须写清：

- schema 变化。
- 数据迁移和回滚。
- 兼容旧数据或旧客户端的策略。
- 数据权限、脱敏、保留和删除规则。
- 验证查询或回归样例。

## 兼容策略

优先考虑：

- expand / migrate / contract。
- 新旧字段并存过渡。
- 读兼容优先，再切写路径。
- 长事务和大表迁移如何分批。
- 索引、默认值、回填任务的风险。

## 回滚路径

没有回滚路径的数据变更必须在风险中明确标注。

回滚时要回答：

- 能否直接回滚代码。
- 数据是否需要逆向迁移。
- 是否会丢失新写入的数据。
- 是否需要补偿脚本。
- 是否要先停写。

## 验证证据

至少考虑：

- 迁移前样例。
- 迁移后样例。
- 回滚或补偿验证。
- 旧数据读取验证。
- 旧客户端或旧接口兼容验证。

## 何时拆 work item

以下情况通常应拆分：

- 先做兼容 schema，再切换行为。
- 先补迁移工具，再做业务功能。
- 先补回归测试，再做危险重构。

## Review Checklist

- 是否明确数据变更类型。
- 是否有迁移和回滚策略。
- 是否验证了旧数据 / 旧客户端兼容性。
- 是否把不可回滚风险写进设计和 closure。
