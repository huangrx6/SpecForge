# PRD Quality Guide

本文件合并 PRD 质量量表和反模式检查。写完 PRD 后读取本文件，先修阻断问题，再修表达。

## Quality Rubric

| 检查项 | 通过标准 |
|---|---|
| 问题清楚 | 能说明为什么做，不只是功能描述 |
| 用户清楚 | 至少有目标角色、场景、使用频率 |
| MVP 清楚 | 第一版做什么、不做什么明确 |
| 决策有依据 | 每个 MVP 项有用户价值、风险或证据 |
| 指标可观察 | 至少 1 个用户价值指标或业务指标 |
| 非目标清楚 | 明确防止范围膨胀 |
| 未决问题可见 | 高影响未知没有被隐藏 |
| AI / 数据风险可见 | 涉及时必须写清质量、成本、安全、人工兜底 |
| 下游交接可用 | 需求阶段能直接转译行为种子 |

P0 问题：

- 没有目标用户。
- 没有 MVP。
- 没有非目标。
- Agent 建议被写成用户确认。
- 成功指标完全缺失。
- 高影响未决问题被隐藏。
- PRD 写成技术方案。

## Anti-patterns

| 反模式 | 失败信号 | 为什么危险 | 修正 |
|---|---|---|---|
| 通用模板倾倒 | 套摘要、市场、发布计划，但不接 SpecForge 产物图 | 下游需求阶段不能用 | 改为产品决策摘要 + 下游交接 |
| 功能清单冒充 PRD | 只有功能清单 | 看不出为什么做和怎么取舍 | 补问题、目标结果和 MVP 理由 |
| 建议冒充决策 | Agent 推荐直接写 MVP | 跳过用户确认 | 改成候选、授权默认或待确认 |
| 需求泄漏 | 写需求编号、验收编号、接口或数据库 | 阶段边界混乱 | 移到需求阶段或技术设计阶段 |
| 缺少非目标 | 没有明确不做 | 实现阶段范围膨胀 | 写非目标和后续触发条件 |
| 指标表演 | 指标都是“提升体验” | 不可判断成功 | 写可观察业务、用户或质量指标 |
| AI 魔法 | 写“智能识别 / 自动生成” | 不可验收 | 写输入、输出、评估、人工兜底 |
| B 端数据盲区 | 不写数据来源、口径、权限 | 后续技术和验收会错 | 写数据与合规快照 |

## 修正顺序

1. 先修决策状态和确认状态。
2. 再修问题、用户、MVP 和非目标。
3. 再修指标、风险和下游交接。
4. 最后删除 PRD 中的需求规格、界面设计和技术设计泄漏。
