# Content

文案是界面的一部分。按钮、空态、错误和提示必须帮助用户完成下一步。

## 按钮

- 使用动词 + 对象：`新建任务`、`导出报表`、`重试同步`。
- 危险操作写清后果：`删除成员`，不要只写 `确定`。
- 同一流程中主按钮文案保持一致，不在提交、保存、确认之间来回切换。

## 错误

- 说明发生了什么、用户能做什么、是否可重试。
- 不责备用户，不暴露内部栈、SQL、密钥、服务器路径。
- 可恢复错误提供操作；不可恢复错误提供联系渠道或追踪 ID。

## 空态

- 空态要说明原因和下一步，不写泛化欢迎语。
- 权限空态和数据空态分开；权限不足不要诱导用户创建数据。

## 输出格式

```md
Primary action: 新建规则
Empty state: 暂无规则。创建第一条规则后，系统将按条件自动分配任务。
Error state: 保存失败，网络连接超时。请稍后重试，或复制追踪 ID 联系管理员。
```
