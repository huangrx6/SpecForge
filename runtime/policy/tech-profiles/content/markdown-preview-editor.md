# Markdown Preview Editor

## 定位

文档、知识库、公开内容发布和内容后台的常用编辑方案。它保留 Markdown 的可迁移性，同时给作者一个可理解的预览体验。

这个 profile 的重点不是“用了哪个编辑器库”，而是把写作体验、渲染安全、资源处理、移动端布局和测试边界说清楚。

## 适合

- 文档站、知识库、发布系统、帮助中心、技术内容后台。
- 作者需要在保存前检查标题层级、代码块、图片和链接。
- 内容最终以 HTML 或静态页面展示，但源数据希望保持 Markdown。
- 第一版需要比 textarea 更好的体验，但不需要 Notion 类块编辑。

## 不适合

- 非技术作者完全不懂 Markdown，且强需求所见即所得。
- 需要复杂表格、嵌入组件、块级拖拽、协同编辑。
- 内容模型不是文章，而是高度结构化的页面搭建器。

## 默认能力

| 能力 | 默认 | 说明 |
| --- | --- | --- |
| 编辑体验 | 编辑 / 预览双模式 | 桌面可双栏，移动端用 tab |
| 存储格式 | 原始 Markdown | 渲染 HTML 可缓存，但不是主数据 |
| Markdown 扩展 | 按需启用 | 表格、代码高亮、目录、frontmatter 要逐项确认 |
| 图片 | 第一版支持 URL 或上传二选一 | 上传涉及存储、鉴权和清理策略 |
| 安全 | sanitizer 必填 | 尤其是用户可输入链接、图片和 HTML 时 |
| 未保存保护 | 必填 | 离开确认、保存状态和错误恢复 |

## 技术选择维度

| 维度 | 轻量方案 | 增强方案 |
| --- | --- | --- |
| 编辑器 | textarea + preview panel | CodeMirror / Monaco / Milkdown Markdown mode |
| 渲染 | markdown parser + sanitizer | remark / rehype pipeline |
| 代码高亮 | 展示端高亮 | 编辑端语法高亮 |
| 图片 | URL 输入 | 上传、资源库、拖拽粘贴 |
| 目录 | 渲染时生成 | 编辑时同步预览 |

不要在 spec 阶段只写“Markdown 编辑器”。必须明确选型、原因、体积影响、维护风险和降级方案。

## 设计必填问题

- 编辑器布局：桌面双栏还是 tab？移动端如何切换？
- 文章字段：标题、slug、摘要、封面、标签、分类、发布日期、SEO 字段是否需要？
- Markdown 功能：表格、任务列表、脚注、代码高亮、目录、frontmatter、内嵌 HTML 是否支持？
- 图片来源：只填 URL、上传到本地、对象存储，还是先不做？
- 预览是否完全等同公开页样式？
- 保存策略：手动保存、自动保存、草稿、发布、撤回分别怎么处理？
- XSS、坏链接、超大文章、上传失败如何反馈？

## 实现约束

- 编辑器源文本、预览 HTML、文章元数据要有清晰边界。
- Markdown 渲染 pipeline 必须复用在后台预览和前台展示，避免两套效果不一致。
- 支持上传时，上传接口必须校验类型、大小、权限，并处理孤儿文件清理策略。
- 预览面板要有空状态、加载状态和渲染错误状态。
- slug 生成、重复校验和手动修改行为必须写入 design。
- SEO 字段不要偷偷从正文截取，除非 spec 明确默认规则和可覆盖方式。

## 推荐组合

- `frontend/next-app-router-tailwind-ts` + `backend/next-api-routes`：需要公开渲染、预览和轻量后台时可组合。
- `database/rdbms-postgresql` / `database/rdbms-mysql`：文章、标签、发布状态、slug 唯一性等关系模型。
- `testing/vitest-playwright`：覆盖编辑、预览、保存、发布和公开页。
- `security/owasp-top10-defenses`：多用户后台、上传和公开渲染必须引入。

## 验证

- 单元测试覆盖 Markdown 渲染、slug、摘要生成、危险 HTML、链接和图片。
- E2E 覆盖创建草稿、预览、发布、编辑后再发布、公开页展示。
- 移动端截图或浏览器验证必须覆盖编辑 / 预览切换。
- 如果支持上传，验证类型限制、大小限制、失败提示和权限检查。

## Spec Review 检查项

- 是否明确 Markdown editor 选型，而不是只写“富文本/Markdown”？
- 是否列出支持和不支持的 Markdown 功能？
- 是否定义预览与公开页样式一致性的验证方式？
- 是否定义内容安全、上传安全和未保存保护？
- 是否把文章模型、发布流和 SEO 字段写清楚？
