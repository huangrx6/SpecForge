# Product UI Layout Quality

Product UI 的质量首先取决于任务结构，不取决于配色。后台、管理端、审批台、工作台、数据运营页如果只剩侧栏、顶栏、指标卡、大空白面板和快捷入口，即使颜色正确，也必须判定为结构失败。

本文件专门拦截“看起来像后台模板，但用户无法完成主要工作”的 UI。

## 1. Product UI 必答问题

设计任何 Product UI 页面前，先回答这些问题；答不上来时不能开始画布局。

| 项 | 必答问题 | 示例 |
| --- | --- | --- |
| 主要使用者 | 谁每天使用这个页面？ | 审核员 / 运营 / 管理员 / 客服主管 |
| 主要业务对象 | 用户在处理什么对象？ | 工单 / 订单 / 用户 / 告警 / 资源 / 合同 |
| 主要任务 | 用户打开第一屏要做什么？ | 审核、分派、排障、追踪异常、确认风险 |
| 决策依据 | 用户需要看到什么才能行动？ | SLA、优先级、状态、负责人、金额、时间、失败原因 |
| 时间范围 | 数据窗口和新鲜度是什么？ | 今日 / 近 7 天 / 最近刷新于 10:24 |
| 失败路径 | 哪类异常最可能推翻页面设计？ | 超时、无权限、数据延迟、接口失败、批量操作失败 |

## 2. 首屏结构契约

首屏必须展示真实工作表面。指标和快捷入口只能辅助主任务，不能替代主任务。

| 区域 | 必须承担 | 禁止 |
| --- | --- | --- |
| 顶部控制区 | 时间范围、范围筛选、刷新状态、当前视图说明 | 只有面包屑、搜索框和头像 |
| 主要工作区 | 队列、表格、异常列表、时间线、诊断链路或待处理对象 | KPI 卡片后接一个大空白卡片 |
| 指标区 | 解释当前工作负载、风险、趋势或阈值 | 只展示大数字和绿色涨幅 |
| 右侧辅助区 | SLA、负责人、最近活动、风险说明、上下文操作 | 4 个通用 icon 快捷入口 |
| 底部 / 次级区 | 趋势、分布、排名、历史记录、审计或导出 | 为了填满画面而继续加卡片 |

## 3. KPI 可行动性规则

KPI 卡不是装饰。每个 KPI 至少满足以下 2 项，否则必须降级为紧凑统计、表格列或过滤器摘要：

- 有口径：说明统计范围和定义。
- 有时间：说明时间窗口和更新时间。
- 有状态：说明正常 / 警戒 / 异常阈值。
- 有解释：说明变化原因或主要贡献项。
- 有入口：能 drill down 到对应对象列表。
- 有行动：能触发过滤、处理、分派、导出或提醒。

## 4. 工作队列规则

待办、告警、审批、工单和运营任务必须像真实队列，而不是静态文本列表。

| 字段 | 是否必需 | 说明 |
| --- | --- | --- |
| 对象标识 | 必需 | 订单号、用户、工单、资源名或告警名 |
| 状态 | 必需 | 待审核、超时、失败、处理中、已完成 |
| 优先级 / SLA | 必需 | 高 / 中 / 低、剩余时间、是否超时 |
| 负责人 | 按需必需 | 多人协作、审批、客服、运营场景必须有 |
| 时间 | 必需 | 创建时间、更新时间、到期时间或触发时间 |
| 下一步动作 | 必需 | 审核、分派、查看详情、重试、忽略、导出 |
| 批量能力 | 按需必需 | 列表超过 20 条或需要重复处理时必须有 |

## 5. 快捷入口规则

Product UI 中的快捷入口必须来自角色任务频率或上下文状态。以下情况不能使用 2x2 icon grid：

- 入口只是“新增、导出、设置、日志”这类通用动作。
- 每个入口没有当前状态、最近使用、快捷键或角色差异。
- 快捷入口占据右侧栏，但主要任务队列缺失。
- 入口和主工作区没有关系。

更好的替代：

| 问题 | 替代模式 |
| --- | --- |
| 常用命令多 | Command Surface / 命令面板 |
| 有未处理事项 | 角色任务队列 / SLA 面板 |
| 需要回到最近对象 | 最近活动 / 最近处理对象 |
| 需要解释指标 | 异常原因 / 风险贡献项 |
| 需要跨页面操作 | 顶部 action bar / contextual actions |

## 6. 空白预算

Product UI 第一屏不能把大面积空白包在卡片里。除非这是 loading / empty / error / permission 状态，并且有恢复动作，否则以下情况为 high severity：

- 第一屏超过 40% 是空白 framed area。
- 大卡片只有标题和 3-5 行文本。
- 右侧栏或主区域高度被拉满，但内容没有真实密度。
- 卡片存在只是为了让页面看起来“完整”。

## 7. 反例诊断：通用后台工作台

| Fail signal | 为什么失败 | 修正方向 |
| --- | --- | --- |
| 侧栏 + 顶栏 + 4 个 KPI + 大空白待办卡 + 快捷入口 | 没有主对象、主队列、异常原因和下一步动作 | 选择 Review Desk / Ops Dashboard / Resource Operations 之一 |
| “待办事项”只有标签和数量 | 不是可处理队列，无法判断优先级 | 补对象、SLA、负责人、时间、动作 |
| KPI 只有数字和涨幅 | 数字不能直接指导处理顺序 | 绑定筛选、阈值、异常解释和 drilldown |
| 快捷入口是 icon grid | 只是导航重复，没有业务密度 | 换成最近活动、命令面板或上下文动作 |
| 主面板大量空白 | 第一屏没有承载真实工作 | 改成表格、队列、时间线、异常分布或详情 inspector |

## 8. 推荐修复模式

| 模式 | 适合 | 第一屏结构 |
| --- | --- | --- |
| Review Desk | 审核、审批、实名、风控 | 状态 tabs + 待处理队列 + 详情 drawer + SLA 侧栏 |
| Ops Dashboard | 运营监控、告警、服务可用性 | 控制区 + 异常摘要 + 趋势 / 排名 + 责任入口 |
| Resource Operations | 用户、订单、资源、合同管理 | 筛选工具栏 + 主表格 + 右侧 inspector + 批量操作 |
| Command Surface | AI 工具、运维工具、低频控制台 | 主输入 / 命令区 + 推荐动作 + 历史结果 + 工具状态 |
| Workflow Timeline | 导入、排障、诊断、流程推进 | 当前步骤 + 阻塞原因 + 恢复动作 + 执行日志 |

## 10. 阻断项

以下任一问题存在时，Product UI 不能通过设计审查：

- 主要使用者、主要业务对象或主要任务未定义。
- 首屏只有 KPI / 卡片 / 快捷入口，没有真实工作表面。
- 工作台主区域是大空白 framed card。
- 待办列表缺少对象标识、SLA / 优先级、时间或下一步动作。
- 右侧栏被通用快捷入口占满，但没有上下文价值。
- high severity visual QA issue 没有修正或明确接受理由。
