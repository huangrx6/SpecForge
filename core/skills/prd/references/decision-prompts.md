# PRD Decision Prompts

本文件保存 PRD 写作前后需要使用的少量决策提示：产品访谈、MVP 切分和开放问题审查。它不是问卷清单；只在缺口会改变 PRD 决策时使用。

## Product Interview

当目标用户、问题、MVP、非目标、成功指标或高风险产品决策不清楚时使用。

规则：

- 只问会改变 PRD 的问题。
- 每轮优先 1 个问题；同一决策面可以合并 2-3 个。
- 问题后说明为什么它会改变 PRD。
- 用户回答后更新假设台账和决策状态。

问题种子：

- 这个功能第一版最主要服务哪个角色？
- 如果只做一件事，必须解决哪个痛点？
- 本期明确不做什么，避免范围膨胀？
- 成功后你希望看到哪个可观察指标变化？
- 哪个风险会阻止进入需求阶段？

## MVP Slicing

把候选功能池裁剪成 MVP、可选增强、后续版本和不在范围内。

表格：

```md
| 功能 | 用户价值 | 复杂度 | 风险 | 切分 | 理由 | 确认状态 |
|---|---|---|---|---|---|---|
```

规则：

- MVP 只保留能证明核心目标结果的最小能力。
- 高价值高风险项优先拆小或放入实验。
- Agent 建议不能等于用户已确认。
- 每个后续版本 / 不在范围内项都要写后续触发条件。

## Open Question Review

用于 PRD 写完前检查高影响未知是否被隐藏。

审查表：

```md
| 问题 | 影响 | 负责人 | 需要时间 | 状态 |
|---|---|---|---|---|
```

阻断规则：

- 影响 MVP、目标用户、成功指标、数据权限、AI 质量、合规、成本的开放问题必须阻断，或指定负责人和需要时间。
- 如果开放问题阻断需求阶段，`decision_status` 不能是 `approved-for-requirements`。
- 低影响未知可以进入假设台账，但要写复核触发条件。
