# 外部事实和官方资料

本参考用于判断什么时候必须查当前外部资料，以及如何选择可信来源。

## 必须查当前官方资料的情况

- SDK、CLI、框架、云服务、AI 工具、协议或规范可能已经更新。
- 用户要求“最新”“当前”“今天”“现在”。
- 安全、合规、金融、医疗、法律或生产部署相关结论。
- 文档中要引用具体命令、参数、版本、错误码或配置字段。
- 仓库内现有知识明显可能过时。

## 来源优先级

1. 官方规范、官方文档、标准组织。
2. 项目源码、release note、README。
3. 维护者公告、issue / discussion。
4. 博客、教程、社区经验，只作补充，不作唯一依据。

## 外部资料如何进入 SpecForge

只沉淀：

- 结论。
- 适用范围。
- 关键约束。
- 链接或引用。
- 是否存在版本敏感性。

不要：

- 大段复制原文。
- 把未经核实的社区说法写进长期规则。
- 用一次性网页内容覆盖项目 SSoT。

## 资料陈旧性判断

优先警惕：

- 版本号、命令参数、云厂商配置。
- 规范草案、协议扩展、SDK breaking change。
- AI 模型、工具能力、支持平台。
- 发布、部署、合规类要求。

## Review Checklist

- 这个事实是否可能过时。
- 是否用了最高优先级可得来源。
- 是否在文档中写明适用范围。
- 是否误把社区经验写成硬规则。
