# NFR Design — 非功能需求设计子模块

本子模块是 `sf-tech-design` 的内部参考，统筹**安全（Security）、可观测性（Observability）、部署（Deployment）和可靠性（Reliability）**四类非功能关切。

**只在本次 work item 对以下任一维度有实质影响时读取**，按需展开对应章节，不强制全量输出。同时读取 `.specforge/policy/rules/security/README.md` 和 `.specforge/policy/rules/delivery/README.md`。

---

## 安全（Security）

**触发条件**：变更涉及认证、授权、数据隐私、外部输入处理或凭据管理。

### 认证与授权

- 认证方案：Session / JWT / OAuth2 / API Key，全局策略统一。
- 授权模型：RBAC / ABAC / ACL，说明权限粒度和继承关系。
- 每个 API 端点的认证要求和权限检查点。
- Token 生命周期：颁发、刷新、撤销（Revocation）策略。

### 输入验证与注入防护

- 所有外部输入必须在边界处校验（长度、类型、格式、枚举）。
- SQL / NoSQL 注入：参数化查询、ORM 使用规范。
- XSS：输出转义，CSP 策略。
- SSRF：外部 URL 访问白名单。

### 数据保护

- 静态加密（at-rest）：敏感字段（密码、Token、PII）加密存储。
- 传输加密（in-transit）：强制 HTTPS / TLS，证书管理。
- PII 数据：识别、最小化、脱敏和访问日志。

### 威胁建模（高风险变更）

- 识别威胁面：谁可以访问、能做什么、破坏性行为是什么。
- 关键风险点和缓解措施。

## 可观测性（Observability）

**触发条件**：变更引入新的业务路径、外部依赖、异步任务或影响系统指标。

### 日志（Logging）

- 日志级别规范：`DEBUG / INFO / WARN / ERROR`，生产环境最低级别。
- 结构化日志：JSON 格式，必含字段（`trace_id`、`service`、`timestamp`、`level`、`message`）。
- 不在日志中记录敏感信息（密码、Token、完整 PII）。
- 关键业务事件必须有 `INFO` 日志（如订单创建、支付完成、用户注册）。

### 指标（Metrics）

- 业务指标：本次 work item 引入的关键业务计数器或直方图（如请求量、错误率、处理时长）。
- 技术指标：P50 / P95 / P99 延迟，资源利用率（CPU、内存、连接池）。
- 指标命名：`<service>_<entity>_<unit>`（如 `order_processing_duration_ms`）。

### 链路追踪（Tracing）

- 跨服务调用必须传播 Trace Context（W3C TraceContext 或 B3）。
- 关键操作（外部调用、DB 查询、队列消息）需创建 Span。

### 告警

- 基于新指标定义告警阈值和通知渠道。
- 区分 P0（立即响应）和 P1（工作时间响应）。

## 部署（Deployment）

**触发条件**：变更影响部署流程、配置、基础设施或需要特定发布策略。

### 发布策略

- **滚动更新**：无状态服务首选。
- **蓝绿部署**：高风险变更，需要即时回滚能力。
- **金丝雀发布**：逐步放量，适合有流量分发能力的场景。
- **Feature Flag**：解耦代码部署和功能发布，适合长期分支或 A/B 测试。

### 配置管理

- 区分代码配置（env var）、运行时配置（Config Map / Consul）和密钥（Secrets Manager）。
- 新增配置项必须：有明确默认值、有文档、在 staging 环境验证后再部署 production。
- 不在代码或 Git 中存储密钥。

### 回滚方案

- 说明如何回滚到上一个版本（镜像 Tag、Feature Flag 关闭、数据库回滚脚本）。
- 确认回滚脚本已在 data-design 中定义（如有数据迁移）。
- 估算回滚时间窗口和影响范围。

### 扩缩容

- 水平扩展（HPA）触发条件和最大副本数。
- 有状态服务的扩缩容限制（如缓存预热、主从延迟）。

## 可靠性（Reliability）

**触发条件**：变更涉及外部依赖调用、异步任务、关键路径或 SLA 承诺。

### 重试与超时

- 外部调用必须设置超时（连接超时 + 读取超时）。
- 重试策略：最大重试次数、退避算法（指数 + Jitter）、幂等保证。
- 非幂等操作（如扣款、发送通知）禁止盲目重试。

### 熔断与降级

- 熔断器（Circuit Breaker）：失败率阈值、半开状态探测、恢复策略。
- 降级策略：服务降级时的用户感知（静默失败、缓存兜底、功能限流）。
- 说明哪些功能是核心路径（不可降级）和非核心路径（可降级）。

### 限流

- 接口级限流：QPS 阈值、窗口大小（固定窗口 / 滑动窗口 / 令牌桶）。
- 用户级 / 租户级限流（多租户场景）。
- 限流响应：HTTP 429，`Retry-After` Header。

### 幂等性

- 对外暴露的写操作（POST、PATCH）建议支持幂等：幂等 Key 生成和存储策略。
- 消息消费幂等：消费方去重策略（唯一 ID 检查、状态机保护）。
